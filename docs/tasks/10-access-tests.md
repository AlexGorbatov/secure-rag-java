# 10. Матрица тестов доступа

## Зачем

Отдельные тесты уже есть в задачах 04–09. Здесь ты собираешь их в одну систему, которая
доказывает главное обещание проекта: **Bob никаким способом не получит ничего из документов Alice.**
Если завтра кто-то сломает фильтр — упадёт именно этот набор.

## Матрица

Для **каждого** эндпоинта, который может вернуть содержимое документа:

| Кто | `GET /documents` | `GET /documents/{id}` | `DELETE /documents/{id}` | `POST /search` | `POST /chat` |
|---|---|---|---|---|---|
| без токена | 401 | 401 | 401 | 401 | 401 |
| токен без групп и чужой | свои только | 404 | 404 | только свои чанки | в промпте нет чужого |
| bob (не в группе) | нет док. alice | 404 | 404 | нет чанков alice | нет текста alice, нет цитат alice |
| bob (в группе `all-staff`, док. расшарен) | есть | 200 | 404 (не владелец) | есть | есть |
| alice (владелец) | есть | 200 | 204 | есть | есть |

## Что создать

- `web/AccessMatrixTest` — `@SpringBootTest` + `@AutoConfigureMockMvc` + Testcontainers + заглушка
  чат-модели.
- В `@BeforeEach` через **API** (как настоящие пользователи) загрузи:
  - `alice-hr.txt` — «Salary bands for 2026 …», группы `[hr]`;
  - `alice-shared.txt` — «Office opening hours …», группы `[all-staff]`;
  - `bob-eng.txt` — «Salary review process for engineering …», группы `[engineering]`.
- Помощники: `alice()` и `bob()` → `jwt().jwt(t -> t.subject(...).claim("groups", ...))`.
- Очистка между тестами: удали строки из `documents` и `vector_store` (`JdbcTemplate`), чтобы тесты
  не зависели друг от друга.

## Приёмы

- **Проверяй отсутствие по содержимому**, а не по количеству: `doesNotContain("Salary bands")` в
  JSON-ответе и в каждом промпте заглушки.
- **Тексты документов — похожие по смыслу.** Иначе тест пройдёт, даже если фильтра нет.
- Оставь один «контрольный» тест, который проверяет, что без фильтра (напрямую через `VectorStore`)
  чанк alice находится по запросу bob'а. Он доказывает, что матрица что-то проверяет.

## Как сделано в проекте

`web/AccessMatrixTest` — 17 проверок через HTTP, матрица целиком в Javadoc класса:

- три документа про зарплаты: Alice `hr`, Alice `all-staff`, Bob `engineering`;
- персонажи: без токена, токен **без `sub`** (но со всеми группами — группы сами по себе доступа не
  дают), **Mallory** (чужой, без групп), Bob, Alice;
- эндпоинты: список, `GET`/`DELETE` по id, загрузка (только 401), поиск, чат — для чата проверяется
  и ответ, и **что ушло в модель** (`StubChatModel`);
- контрольный тест: поиск без фильтра находит все три текста по вопросу Bob.

Два эксперимента — матрица ловит поломку каждого из двух независимых механизмов защиты:

- «сломай `AccessFilter`» (векторный фильтр пропускает всё) → падают **5** проверок: поиск и чат у
  Bob, у Alice (видит чужое), у «без `sub`» и у Mallory;
- «сломай проверки в репозитории» (`findAll`/`findById` вместо запросов с правами) → падают **6**:
  список, `get`, `delete` у Bob, у «без `sub`» и у Mallory.

Список/`get`/`delete` не зависят от векторного фильтра, а поиск/чат — от запросов репозитория,
поэтому каждый механизм нужен и проверяется отдельно.

Более узкие тесты по слоям остаются: `DocumentRepositoryTest`, `RetrievalServiceTest`,
`ChatServiceTest`, `DocumentAccessApiTest`, `SearchApiTest`, `ChatApiTest`.

## Готово, когда

Вся матрица зелёная. Попробуй **сломать** `AccessFilter` (например, верни пустой фильтр) и убедись,
что падают несколько тестов сразу. Верни как было.
